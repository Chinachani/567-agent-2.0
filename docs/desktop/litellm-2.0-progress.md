## 本批实现

- Desktop/Android 开发版本标记为 2.0.0，未创建发布标签。该版本号不表示官方通道已完成。
- 桌面入口在加载业务模块前设置独立 Home、Agent 配置、Electron userData/sessionData 和 Action RPC；开发与打包预览都拒绝复用 1.x 路径。解析现有父目录的真实路径，拒绝 2.0 根目录转向其他数据目录，包含 Windows 更新存储和缓存的边界检查。
- 新增 `bun run dev:v2` 和只打印配置的 `bun run dev:v2:config`。应用目录的 `bun run dev`、`bun run start` 同样使用隔离启动器。默认 Vite 端口 3022，官方云功能暂时关闭。
- 移除可直接使用已安装 1.x 数据的开发命令；本批预览不注册覆盖正式 `567-agent` 的全局命令。宿主所需的专属 CLI 路径仍保存在隔离设置中。
- cloud 或降级 IPC 在主窗口开始加载之前注册，不等待远端网络。无云构建的刷新与订阅返回遵守原有结构；退出时释放 cloud IPC、唤醒 hooks 和 Bridge。
- UI 验证环境的 dev/debug/fresh 数据与 RPC 端点纳入 2.0 根目录，debug 仅从 2.0 开发数据取必要配置。本批未启动 UI 验证实例。
- Android 基础包名改为 `com.api567.agent.v2`，测试包为 `com.api567.agent.v2.test`；显示为 2.0 开发版。桌面默认发布配置和手机更新查询改用 2.0 仓库。

这批只建立可开发的隔离基线并调整 cloud 启动生命周期。它没有完成 LiteLLM 推理、2.0 登录、订阅核销或 NewAPI 数据迁移。

## 接下来的实施顺序

1. 将构建、运行时与双端配置中的业务地址和模型网关地址分别定义。替换官方自动 NewAPI 接入，沿用原生 cloud/Bridge 的宿主边界，不另建并行认证体系。
2. 确定业务后端归属、登录方式、测试地址及模型授权合同；完成刷新账号代次、响应体期限、注销和凭证热重载的升级。
3. KMP 拆分业务客户端、模型网关客户端和 DTO，按连接所有权管理替换与在途请求；官方注销不影响自定义供应商。
4. 对接富模型目录、推理与工具回放、usage、计费操作身份及取消对账。1.2.13 新增的上下文压缩也需要独立模型 operationId；远程 turnId 用于任务恢复，不能直接替代模型收费操作身份。
5. 完成官方账号 UI、订阅与按量兜底，以及经过用户确认的旧配置迁移；保留全部本地会话、附件和有效自定义默认模型。
6. 最后执行合同与行为回归、两端打包及实机验收。未完成这些步骤前不发布用于日常替换 1.x 的版本。

## 持续同步 1.x

本机通过 `source-1x` 拉取原仓库。每次同步记录源提交、受影响模块与冲突决策；2.0 的数据隔离、凭证边界、更新源和新接口合同不得被旧版本覆盖。同步后重点核对手机发送/压缩/恢复、远程协议、附件和媒体、运行时及资源保护。

1.x 会话确认的局域网首次配对诊断缺口继续跟踪：正常升级应保留配对，旧凭据被拒和恢复失败需明确区分；不能把所有连接失败都当作需要重置证书。
