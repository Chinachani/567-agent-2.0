# 2.0 独立开发数据与 cloud 启动顺序

## 背景

1.x 仍在持续更新。早期 2.0 仅有方案文档，使用与 1.x 共享远程配置的 Git worktree；直接修改 origin 会影响主仓库。旧开发目录和 Android 测试包身份也可能与 1.x 重合。原生 cloud 在 Renderer 开始加载后才注册 IPC，入口未持有其清理函数。

## 决策

- 新 GitHub 仓库使用独立检出，基线为 v1.2.13。保留 1.x 历史和只读同步来源，先制作可核验备份再开始修改。
- 当前 2.0 仅为开发预览，数据全部限制在用户 Home 下独立的 `.567agent-v2-dev` 根目录，项目内配置使用 `.567agent-v2-*`。主进程第一个副作用模块先设置路径，再求值其他业务模块；包括本地打包预览。不得自动迁移或复用正式数据。
- 环境变量中的 Home、Agent 目录、userData、Action RPC 端点及 Windows 更新路径需要通过同一边界校验。UI 验证数据同样隔离。预览不替换正式全局 CLI 命令，Android 使用独立 v2 包身份。
- 桌面继续沿用 cloud/Bridge 分层。cloud 与无官方服务的降级处理器均在 Renderer 加载前注册，注册过程不依赖远端请求；入口拥有退出清理职责。
- 官方业务与模型协议的完整改造随后实施，开发启动器暂时关闭云服务。新版更新来源与 1.x 分开。

## 备选方案与后果

仅设置 `AGENT567_HOME` 无法隔离 Electron、项目配置、RPC 和 Windows 更新目录。仅修改开发启动命令也无法保护直接启动及模块加载时的路径副作用。因此采用统一解析器与提前运行的入口。

预览期间限制自定义数据根必须位于 v2 目录下，使用旧数据的开发命令不再提供。生产 2.0 的存储位置、正式身份与经过确认的数据迁移另行实施；本决策不宣称已经完成订阅后端或 LiteLLM 接入。
